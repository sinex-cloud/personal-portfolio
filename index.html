Secure CI/CD Delivery Pipeline on GCP

A push to main is tested, scanned for secrets and vulnerabilities, and goes live on two Google Cloud servers in under two minutes, with no manual steps. Scroll through one real run.

Decisions I can defend

      
    
        
  • Firewall scoped by network tag.It opens ports 22 and 80 only on the two web VMs, never on other machines in the shared GCP project.
    • 
        
  • One image per commit.Images are tagged with the commit SHA, so each server runs a version that traces back to exactly one commit.
    • 
        
  • Secrets never touch the repo.The Docker Hub token and a dedicated deploy key live in protected GitLab CI/CD variables.
    • 
        
  • Scanned on every push.gitleaks checks the full git history for secrets, Checkov the Terraform, ansible-lint the playbooks and Trivy the container image. Findings are fixed or accepted with a written reason.
    • 
      

      
What production would addIAP or a bastion host instead of SSH open to the internet · a load balancer and rolling deploys · a dynamic inventory · monitoring and alerts on the /health endpoint

The demo VMs are shut down to save cost, so the deploy step is switched off. The scans still run on every push. One terraform apply and a push bring the servers back.
